## Goal
Extend the userscript, Export-HelloID.ps1 and helloid-mcp from Provisioning-only to Service Automation (Self-Service, Delegated Forms, Automation), Directory, Applications, Security/Authentication and Settings: export, backups, import, MCP management behind separate flags, plus two table columns.

## Decisions made by the owner (fixed)
- Column 'Last used' on /admin/delegatedforms/ counts SUBMITTED forms only. Column 'Last requested' on /admin/selfservice/products/ INCLUDES cancelled and denied requests.
- Userscript never uses the public API (admin session only). MCP gets API credentials via its configuration; PowerShell script via parameters (SecureString/credential, never logged, never exported).
- MCP reads are flag-gated as well as writes; browser/API are only permission-restricted. Run-flags (anything that runs a task/form) are separate from read/write flags. Separate flags per area (serviceAutomation, delegatedForms, directory, security, settings, ...), backup/restore flags too. DESIGN.md must be updated before adding flags (its rule: no undocumented features).
- API-first wherever the public API covers a family (security, stability, maintainability, token cost); admin session for the rest.
- NEVER hard-code hostnames. Only Training tenants run on *.helloid.training; other environments use any domain. Derive API base and portal URLs from the configured environment URL.
- Browser write tests on the Training tenant are allowed (create/edit/delete test objects named zz-uxtest-*), EXCEPT security settings (roles, policies, IdPs, SMS/RADIUS, API keys, 2FA, password/mobile settings) and Settings pages. The owner paused work once: agents were stopped. Always clean up zz-uxtest-* objects.
- Project rules: DryRun guard on target-system scripts; HelloID Provisioning has no API-key auth (admin session only); answer questions before implementing; delegate non-small builds to agents.

## Verified findings (short)
- Admin UI transport: portal host; Service Automation gateway discovered via GET //api/v3/sa/url/<module> (modules seen: activity, delegated-forms, jobs, product, recertification), calls go to <gateway>/service/<module>/api/...; other lists on portal /server/v2/..., legacy MVC /admin/<Controller>/getall (Kendo keys take, skip, page, pageSize, virtual); Settings pages are server-rendered HTML forms with anti-forgery token; 2FA pages are cross-origin iframes. Userscript currently captures only a header from hosts matching /gateway/i and routes by location.hash: both need changes for SA (path-routed, host without 'gateway').
- Column data: activity = SAGW GET /service/activity/api/activities/delegated-forms?language&skip&take&search&searchFields (rows carry form GUIDs); request history = SAGW GET /service/product/api/requests/history?language&skip&take&search&searchFields&onlyrecertification. Response bodies NOT yet captured (field names, timestamp format, cancelled/denied status values unknown). Both target tables are AG Grid (Angular): add columns via grid API (findGridApi + setColumnDefs); GUID in row data (delegated forms node.data.id, products node.data.selfServiceProductGuid).
- Public API (gitignored/HelloID_Original.yaml, identical to _Bundled.yaml; 35 paths; keep these local, they are gitignored): covers delegated forms/categories, dynamic forms, data sources, products, product categories, variables, tasks (partial), groups, users, roles, agent pools (list), applications (shell only). NOT covered: approval workflows, activity/request history, Systems, schedules, application categories, mapping sets, AD configs, IdPs, access rules, sign-on/password policies, password self-service, mobile app, API keys, 2FA/OATH, SMS, RADIUS, certificates, Settings. Live probe confirmed read access, N+1 pattern (delegated form task and product actions only on single GET), secret variables returned in clear (must mask), /product-assignment lacks denied/cancelled, 'take' ignored on /delegatedforms. Write probe: create/update/delete verified for variables, delegated form categories, product categories, dynamic forms (update = new version, same formOriginalGUID), delegated forms (GET body round-trips), static data sources, groups; client-supplied GUIDs rejected.
- Secrets seen in UI: Entra SCIM secret shown in cleartext, API key secret present in page HTML, an API key Note column held a pasted key/secret, IdP client secrets are plain inputs. All must be masked in exports. Recommend rotating the Entra SCIM secret and the API key whose credentials were pasted in chat.
